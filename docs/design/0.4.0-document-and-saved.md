# LinScanner 0.4.0 — Document and Saved: technical concept

Written 2026-09-23, before the work starts. It covers the requested changes, the model behind them,
the decisions taken, and what each part will look like when it's done.

## 1. What was asked

1. **Save As doesn't open a dialog**, for the document and for a crop.
2. **Save All has no icon.**
3. Rename **Preview → Document** and **Recent → Saved**.
4. **Saved** page: a document list on top, a **preview pane** below, a **search field**, the preview
   **collapsible**, **rename in place** by clicking the file name, **single click** previews, **double
   click** opens the document in Document.
5. **Document** page: regroup the toolbar by function (page operations together, editing together,
   next to each other but not merged).
6. **Crops become new thumbnails**, labelled **crop 1, crop 2, …**, kept in memory until saved, never
   replacing the page they came from (30 crops of one page = 30 thumbnails).
7. **Thumbnails can be renamed**, and that name becomes the suggested file name: **Save** uses it,
   **Save As** offers it in the dialog for the user to change.

### Reading of the two rename sentences

The request says "rename the 'Recent' button to 'Document'" and then "rename the 'Recent' button to
'Saved'". Taken with the rest of the request — *"double-clicking … brings the user back to the
'document' page (formerly 'preview')"* — this is read as:

| Old | New |
|---|---|
| Preview | **Document** |
| Recent | **Saved** |

## 2. The two bugs (fixed first, already done)

| Bug | Cause | Fix |
|---|---|---|
| Save As does nothing | `icon_button` calls its action with no arguments; `on_save_as(self, _btn, …)` needed one, so every click raised `TypeError` before the dialog opened. It appeared when Save As became an icon button | `_btn` now defaults to `None` |
| Save All has no icon | the button is created hidden (`set_no_show_all(True)`) and later revealed with `show()`, which shows the button but not its child image | reveal it with `show_all()` |

## 3. The model: pages, names and crops

Today a page is `{"path", "rotation", "dpi", "mode", "doc", "overlays"}` and crops replace the page's
image. Three fields are added, and nothing is written to disk until the user saves:

| Field | Meaning |
|---|---|
| `name` | what the thumbnail shows and what Save uses as the file name (e.g. `crop 1`, or anything the user types). Empty means "Page n" |
| `source` | the page this one was cropped from (its index at the time), so crops can be grouped and explained |
| `crop_of` | the *name* of the source page, used to number crops per page |

**Crops.** `apply_crop` no longer edits the page in place. It:
1. flattens the source page (rotation and any text or signature baked in),
2. crops it to the chosen rectangle and writes a PNG into the session folder (temporary, as scans are),
3. **appends a new page** right after the source page, named `crop 1`, `crop 2`, … counting the crops
   that already exist for that source,
4. selects the new page so the result is what you see.

The source page is untouched, so 30 crops of page 1 give 30 extra thumbnails, all in memory (the
session folder) until saved. Undo (Ctrl+Z) removes a crop exactly as it removes any other change.

**Names.** A thumbnail's caption becomes editable: click the caption of the selected thumbnail (or
press F2) and type. The name is used, in order of preference:

| Action | File name used |
|---|---|
| **Save** (document with a file) | the document's existing file |
| **Save** (new document) | the page or document name, else the current automatic name |
| **Save As** | the same name, pre-filled in the dialog, editable as usual |
| **Save this page as…** | the page's name, pre-filled |

Names are cleaned for the filesystem (no `/`, trimmed, length-capped) when they reach a dialog.

## 4. Document page (formerly Preview)

Toolbar, left to right, each group boxed as today and wrapping on narrow windows:

| Group | Buttons |
|---|---|
| **History** | undo, redo |
| **Pages** | add pages, duplicate, delete, clear all |
| **Arrange** | rotate left, rotate right, rotate 180°, move left, move right, reverse order |
| **Edit** | **crop**, add text, signature (feature modules attach here) |
| **Export** | save this page as…, **Save**, **Save All**, **Save As…** |

Changes from today: crop moves out of *Arrange* into a new **Edit** group with the Quick Edit tools;
"save this page as…" moves from *Pages* to **Export** next to the other saving actions; the page
navigation stays at the top where the title used to be.

## 5. Saved page (formerly Recent)

```
 ┌───────────────────────────────────────────────────────────────┐
 │ Search […………]   Clear ▾ [All]  [Clear]           4 document(s)│
 │ Date saved   Folder        File name      Format  Pages   🗑   │  ← list (top half)
 │ 2026-09-23   ~/Documents   Scan 1.pdf     PDF     3       🗑   │     single click: preview
 │ …                                                             │     double click: open in Document
 ├───────────────────────────────────────────────────────────────┤
 │ ▾ Preview   Scan 1.pdf · 3 pages            [open] [folder]   │  ← collapsible header
 │            ┌──────────┐                                       │
 │            │  page 1  │   ◀ ▶   page 1 of 3                   │  ← preview pane (bottom half)
 │            └──────────┘                                       │
 └───────────────────────────────────────────────────────────────┘
```

- **Search** filters as you type, over the file name and the folder.
- **Preview pane**: the first page of the selected document, rendered with the existing
  `manager_documents.open_document` + `DisplayCache`, with page navigation. It is **collapsible**
  (an expander, remembered in settings as `saved_preview_open`), and takes the lower half through a
  `Gtk.Paned`, so the split can be dragged.
- **Rename in place**: the File name cell becomes editable (`Gtk.CellRendererText.editable`). Renaming
  moves the file on disk (`os.rename` within the same folder), keeps the extension, refuses a name
  that already exists, and updates the entry. The Recent list is the record of saved documents, so the
  rename is a real file rename, not a label.
- **Single click** selects and previews. **Double click** (or Enter) opens the document in **Document**
  by way of the existing `open-document` event.

## 6. What could go wrong, and the answers

| Risk | Answer |
|---|---|
| 30 crops of a 600 dpi page could fill memory | crops are files in the session folder like scans, not in memory; only thumbnails and one large view are cached (unchanged) |
| A rename could overwrite another file | refuse if the target exists; report it in the status line |
| A renamed file might be lost from the list | the entry's path is updated in `recent.json` in the same step |
| Crops could confuse "Save" (which document?) | a crop belongs to the same document as its source; Save behaves as before |
| Preview of a large PDF could be slow | render only the shown page, and only when the pane is open |
| Old settings and routes (`preview`, `recent`) | the navigation keeps the old route names as aliases, so nothing else in the app or its tests breaks |
