Requested 2026-09-21, after the user's live test of the 0.3.0 working build
(commit `2a513b0`). This document records each change, how it is built, and
how the same idea can be reused elsewhere in linscanner. It is written before
the build; §11 is updated with the outcome afterwards.

## 1. Heroicons

**What.** The standard, MIT-licensed Heroicons v2.2.0 set (Tailwind Labs)
replaces theme icons such as the red Mint folder, and replaces text on
buttons whose function is obvious (delete, zoom, apply to all pages). Every
icon keeps a tooltip, so its meaning stays discoverable.

**How.**
- **Files.** Only the icons linscanner uses are copied into
  `resources/icons/heroicons/{24/outline,20/solid}/`, with the MIT `LICENSE`.
  The full set stays in `~/projects/assets/Icons/heroicons` (see its
  `INDEX.txt`). Copying only what's used keeps the repo small and offline.
- **Colour.** The SVGs draw with `currentColor`. `util_icons.icon(name,
  size, color=None, style="outline")` reads the SVG and replaces
  `currentColor` with the theme's text colour (or a given colour). It then
  renders it with `GdkPixbuf.PixbufLoader` (librsvg, already part of GTK) and
  caches the result per (name, size, colour).
- **Buttons.** `util_icons.icon_button(name, tooltip, on_click)` gives a
  flat, square button with just the icon. `icon_label_button(name, label)`
  gives an icon followed by a short label, for actions such as Apply
  Signature.
- **Credit.** About → Credits lists "Icons: Heroicons by Tailwind Labs (MIT)".

**Icon map.**

| Function | Heroicon |
|---|---|
| Open folder (Recent) | `folder-open` |
| Open document (Recent) | `document-text` |
| Delete row / item | `trash` |
| Select / move tool | `cursor-arrow-rays` |
| Add Text tool | `pencil` |
| Alignment guides on/off | `viewfinder-circle` |
| Apply to all pages | `square-2-stack` |
| Apply Signature | `finger-print` + label |
| Choose or create signature | `pencil-square` |
| Zoom out / in / fit | `magnifying-glass-minus` / `magnifying-glass-plus` / `arrows-pointing-in` |

**Reuse.** Any page can call `icon_button("name", "tooltip", callback)`. To
add an icon, copy its SVG from the assets folder into
`resources/icons/heroicons/<set>/`; names are listed in the assets
`INDEX.txt`.

## 2. Scan Type (was "Source")

**What.** The scanner's own source names ("ADF Front", "ADF Duplex",
"Flatbed", "Automatic Document Feeder") are replaced by what the user means:

- **Front Page**: one side of each sheet.
- **Front & Back**: both sides (duplex). Shown only when the scanner can
  scan duplex.
- **Flatbed**: shown only on scanners that have both a flatbed and a feeder.
  A flatbed-only scanner shows just Front Page.

**How.** `scan_types(caps.sources)` in `manager_scan.py` maps the device
sources to `{"front": source, "both": duplex source, "flatbed": source}`. The
feeder's simplex source is preferred for Front Page. Recognition uses the
existing `FEEDER_SOURCE_HINTS` / `DUPLEX_SOURCE_HINTS`. The Scan page shows a
segmented control, which sends the mapped device source in the request. The
choice is remembered (`scan_type` setting). **Sheets** (all at once / one at
a time) stays for feeder types.

**Reuse.** Any other device option with cryptic names (for example
`--adf-skew`) can be mapped the same way: a pure function from device values
to user choices in `manager_scan.py`, plus a control on the page.

## 3. Paper sizes and Auto-Detect

**What.** Grouped choices (the combo box shows separators between groups):

| Group | Sizes |
|---|---|
| — | **Auto-Detect** (fits the scan to the paper): the new default |
| Documents | Letter, Legal, Executive, Half Letter (Statement), A4, A5, A6, B5 (JIS) |
| Receipts | Receipt 80 mm (till roll), Receipt 58 mm (card terminal) |
| Cards | Business card (3.5 × 2 in), ID / credit card (85.6 × 54 mm), Index card 3 × 5 in |
| Photos | Photo 4 × 6 in, Photo 5 × 7 in |
| Other | Check (6 × 2.75 in), Full scan area |

**Auto-Detect: how, and what "if possible" means.**
1. **Scan the whole area.** The scan uses the full width and the maximum
   length (the ES-400 II takes up to 393.7 mm). The scanner's own paper
   detection (`--adf-crp=yes` on epsonds; auto-size options on other
   drivers, found through the device options) is switched on when present.
2. **Software crop to the paper.** `util_autodetect.content_box(img)`:
   - estimate the background colour from the image's outer border;
   - mark pixels that differ from it by more than a threshold, on a
     downscaled copy (fast);
   - ignore specks by requiring a minimum run of content per row and column;
   - take the bounding box, add a 1.5 mm margin, and crop.
3. **Limits (why "if possible").**
   - When the paper and the feeder background are the same colour (white
     paper on a white backing), the edges can't be seen, and the page is
     kept at full size. It is logged as "auto-detect: no edges found".
   - Very pale paper on a pale background can crop slightly inside the paper
     edge. The margin keeps content safe, and the user can choose a fixed
     size instead.
   - Auto-Detect runs before deskew and blank removal (step 0 of
     `process_page`), and replaces the auto-crop module's overrun trim for
     that page.
4. **Receipts and cards** use a fixed width with an automatic length:
   - The width is the chosen size's width, centred, because the ES-400 II
     feeder centres paper.
   - The length is the maximum, then the software trim above cuts it to the
     paper length. Receipts vary in length, so this avoids a fixed length.

**Reuse.** New sizes are one line in `PAPER_SIZES` (`group`, `label`, `mm`,
and `length: "auto"` for variable length). Other content-based cropping (for
example cropping photos off a flatbed) can reuse `content_box()`.

## 4. Quick Edit: Apply Signature

**What.** Quick Edit is for applying signatures, not for making them. The
signature slots and the create controls leave the Quick Edit panel. It keeps
two controls:

- **[Apply Signature]** applies the current signature: the pointer becomes a
  crosshair, and a click on the page places it (drag the corner to resize).
  With no current signature, it opens the chooser instead.
- **[✎] (pencil-square icon)** opens the **Signature chooser**, a popover card:
  - up to 4 saved signatures on white tiles; click one to make it current
    and place it;
  - a trash icon on each tile removes that signature;
  - **Create Signature** opens the creation dialog, which has two ways in:
    **Type it** (name plus the signature-font browser) and **Upload a PNG**
    (with the "make white transparent" offer). Saving adds the signature to
    a slot (4 max) and makes it current.

The current signature is remembered between sessions (setting
`current_signature`).

**How.**
- `SignatureChooser(Gtk.Popover)` is attached to the edit icon.
- `SignatureCreator(Gtk.Dialog)` is the former font browser plus the PNG
  upload, in a `Gtk.Stack` with a `StackSwitcher`.
- The library code (`utils/util_signatures.py`) doesn't change.

**Reuse.** The same chooser / creator split suits any saved asset, such as
stamps ("APPROVED", "PAID") in a later version: a library in `util_*`, a
popover to pick, and a dialog to create.

## 5. Quick Edit pointer and editing behaviour

**What.** In the Select tool, the pointer tells you what a click will do:

| Pointer over | Cursor | Click / drag |
|---|---|---|
| The **frame** of an item (a 6 px band around its box) | hand (`grab`, `grabbing` while dragging) | drag moves the item (with alignment guides) |
| **Inside** a text item | text cursor | click places the caret and you can type (Backspace, Enter for a new line, Esc to finish) |
| Inside a signature | hand | drag moves it |
| The corner square of the selection | diagonal resize | drag resizes |
| Empty page | arrow | click deselects |

In the Add Text tool, the text cursor shows everywhere. A click inside
existing text edits it; elsewhere, it starts new text.

**How.** `_hit()` returns `(item, zone)` with zone in
`resize | frame | inside`. `on_motion` without a drag sets the cursor from
the zone. `on_press` routes: frame → move drag; inside a text item → start
editing; inside an image → move drag.

## 6. Button sizes

**What.** Buttons are as wide as their label (plus padding) and as tall as
the sidebar buttons (28 px), never stretched.

**How.**
- CSS in `manager_theme_applicator.py`: `button { min-height: 28px;
  padding: 2px 12px; }`, with icon buttons `padding: 2px 6px`.
- Buttons are packed `expand=False`, and stacked buttons (Save / Save As)
  get `halign=END` so each keeps its own width.
- `SegmentedControl` buttons keep their label width.

## 7–8. Recent as a table

**What.**
- A table (`Gtk.TreeView` in a scrolled window) with uniform rows and
  fixed-width columns: **Date saved** · 📂 (open folder) · **Folder** ·
  **File name** · 📄 (open) · **Pages** · **Format** · 🗑 (remove from list).
- It is sorted by date, newest first. Column headers can re-sort, but
  newest-first is the default each time.
- Controls above the table: **Clear** [All ▾] with *All, Older than 5 / 10 /
  20 / 30 / 60 / 90 days*. Clearing removes entries from the list only; the
  files are never touched, and a confirmation says so.

**How.**
- A `Gtk.ListStore` with the rows. Icon columns use `CellRendererPixbuf`
  with Heroicons pixbufs; `set_fixed_height_mode(True)` makes the rows
  uniform.
- Clicks: `button-press-event` with `get_path_at_pos()` gives the column,
  which runs the folder, document or trash action. Enter on a row opens the
  document.
- `manager_documents.clear_recent(older_than_days=None)` does the clearing.

**Reuse.** The icon-cell pattern (a pixbuf column that acts on click) works
for any list with row actions.

## 9. About: compatibility

A **Compatibility** card:
- **Scanners:** USB scanners with a SANE driver (80+ open-source drivers, plus
  vendor drivers such as Epson's), and IPP-over-USB multifunction printers.
  Verified on the Epson ES-400 II.
- **Systems:** Linux Mint 22 (tested), Ubuntu 24.04 and other Debian-based
  systems with Python 3.10+ and GTK 3; other distributions with the same
  packages should work.
- **Files:** saves PDF (and PDF/A), PNG, JPEG, TIFF; opens PDF, PNG, JPEG, TIFF.
- **Not yet:** Wi-Fi / network scanners; OCR languages other than English.
- A note that compatibility is ever evolving: each release adds and verifies
  devices, and reports of what works are welcome.

## 11. Outcome (2026-09-21)

**Shipped:** all nine items, as designed.

**Deviations and details:**
- **Apply Signature.** The request said both "Apply Signature opens a card
  with the existing signatures and Create Signature" and "an edit icon next
  to Apply Signature chooses or creates a different signature". The build
  reconciles them:
  - Apply Signature places the current signature directly, and opens the
    chooser card only when none is chosen yet;
  - the edit icon always opens the card.
- **Auto-Detect** uses the scanner's outer border as the background colour
  (not the page centre, which on a narrow receipt is mostly background). It
  only accepts a box that is mostly "paper" pixels, so a white page on a
  white backing is kept whole instead of being cropped to its text.
- **Receipts, cards and checks** fall back to their nominal size (centred
  across, from the top) when the edges can't be seen. Documents and photos
  scan at their fixed size as before.
- **Two-row thumbnails** fill column by column (1 and 2 stacked, then 3 and
  4, …), so neighbouring pages stay next to each other while the strip
  scrolls sideways.
- **Fixed on the way:**
  - the Sheets row could stay empty after choosing a feeder: `show_all()`
    skips the children of a no-show-all row;
  - the Recent table's icon column type (`GdkPixbuf.Pixbuf`, not `object`).
- **New dependency:** `librsvg2-common` (the SVG loader for the icons),
  already in the offline pool; added to `install.sh` and `app.json`.

**Verification:**
- 103 tests pass; black and pyflakes are clean.
- A scripted walkthrough with SANE's virtual scanner checked:
  - Scan Type and Auto-Detect in the summary;
  - page switching (24–27 ms);
  - Save and Recent, and reopening a saved PDF;
  - Quick Edit zones and cursors, and choose → place;
  - the Create Signature dialog;
  - screenshots in `docs/images/`.
- Not yet checked on the ES-400 II:
  - Auto-Detect on a real receipt or card;
  - the colour of the feeder background, which decides whether edges can be
    seen;
  - the new pointer behaviour by hand.
