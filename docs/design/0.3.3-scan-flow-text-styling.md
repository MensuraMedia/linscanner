# Design: 0.3.3 scan status, Single Page flow, text styling, fonts, save location

Requested 2026-09-21. Written before the build; §7 records the outcome.

## 1. Detect Scanner: power icon instead of the red status text

The detection result sits next to the scanner list instead of in the status
line at the bottom of the page:

```
Detect Scanner
[Find] [ Epson ES-400II ...                    ▾ ] (⏻) [Devices]
                                                    ⏻ Device may be off. Check power settings.   (red, only when not found)
```

- The Phosphor `power` icon is **green** when the scanner answers, and
  **red** when it can't be found or reached.
- In the red state, the message "Device may be off. Check power settings."
  sits beside the icon.
- The spinner replaces the icon while searching.
- Detection messages ("Looking for your scanner…", "Scanner Found", "Unable
  to detect scanner") no longer go to the bottom status line, which stays for
  scanning progress and scan errors. The details still go to the log, and the
  icon's tooltip gives the plain reason.

## 2. Scan Options

- The card title "Options" becomes **Scan Options**.
- The Scan Type row loses its "Scan Type" label (the control speaks for
  itself); the control stays aligned with the others.
- **Sheets** labels: **Multi-Page** (was "All sheets": every sheet in the
  feeder) and **Single Page** (was "One sheet at a time").

**Single Page flow.**
1. Scan takes exactly one page (one sheet, or one sheet's two sides with
   Front & Back) and then stops.
2. linscanner opens Preview so the page can be checked and saved. There is
   no "Scan next sheet" / "Done" step any more.
3. The user presses **Scan** again for the next page:
   - If the previous page(s) were saved, a **new document** starts, and the
     saved file stays in Recent.
   - If they weren't saved, the new page is added to them, so nothing is
     lost, and the status says so.
- "Saved" means nothing has changed since the last Save / Save As
  (`ScanManager.mark_saved()` / `is_saved()` compare page signatures).

## 3. Quick Edit: text styling like a text editor

- **The resize handle is for signatures only.** Text items no longer show a
  corner square, and dragging can't scale text.
- **Text items hold styled runs:**
  `{"type": "text", "runs": [{"text", "font", "size_pt", "color"}], "x", "y"}`.
  Older items with a single `text` / `font` / `size_pt` / `color` still load.
- **Editing.** Click inside text to put the caret there.
  - Drag, or Shift + arrows, to select; double-click selects a word, and
    Ctrl+A selects the whole item.
  - Typing replaces the selection.
  - Backspace and Delete, arrows, Home / End.
- **Styling.** With words highlighted, changing the font, size or colour
  styles only those words. With nothing highlighted it applies to the whole
  item, and new text continues the style at the caret.
- **Rendering.** Runs are drawn left to right on a shared baseline, with one
  renderer for the canvas and for saving (`render_runs`), so the saved file
  matches the screen. The selection is drawn as a translucent highlight.

## 4. Signature fonts: two

Only two bundled signature fonts remain, both SIL OFL 1.1 (bundling
explicitly permitted):
- **Great Vibes** (Robert Leuschke): a classic formal script;
- **Sacramento** (Astigmatic): a light, casual monoline hand.

The other eleven are removed from `resources/fonts/signature/`. Signatures
already saved are PNG images and are unaffected. Users can still add fonts
of their own (Create Signature → Add fonts…).

**Credits.** The About page no longer lists signature fonts. Font credits
live in backlog #33, which now covers only these two fonts (thank the
authors, donate when possible). Each font's `OFL.txt` stays next to it, as
the licence requires.

## 5. Default save location

- Settings → Scanning shows **Default save location**, with the full path and
  a **Choose…** button (a folder dialog).
- **Save** of a new document goes there. **Save As** and **Save page as…**
  start there, or in the current document's folder.
- **Fix:** saving no longer overwrites the default with the last folder used;
  that overwriting was why a chosen default didn't stick.

## 6. Tests

- Single Page request limits and the new-document rule (`is_saved`).
- Runs: splitting a selection, styling it, rendering widths, and old-item
  compatibility.
- No resize zone for text.
- Two bundled fonts.
- The default save location is kept after saving elsewhere.

## 7. Outcome (2026-09-21)

**Shipped:** everything in §1–5, as designed.

**Details:**
- **Saved state.** The rule "a saved document is complete; the next Scan
  starts a new one" applies in both Multi-Page and Single Page, because the
  saved state is the same in both. Unsaved pages are always kept and added
  to.
- **Front & Back with Single Page** scans one sheet, which gives two pages
  (front and back).
- **Styling.** With nothing highlighted, a style change applies to the whole
  text item (the usual quick-edit behaviour), and new typing continues the
  style at the caret.

**Open question to the user:** "looks like some former settings are
missing". Every earlier Scan page setting is still there, renamed or
extended (Source became Scan Type; Paper size became Document Size), and
Blank Pages was added. The user was asked which setting they mean.

**Verification:**
- 113 tests pass; black and pyflakes are clean.
- Screenshots were checked: power icon green and red, Scan Options,
  Multi-Page / Single Page, highlighted "PAID" at 28 pt in red, and the
  Settings default save location.
