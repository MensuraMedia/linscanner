# 0.4.0 Document & Saved, 0.4.1 licence — 2026-09-24

## Requested
One message from the user: two bugs, then seven changes, with "document all these changes, and create
a technical concept document of the new features, then begin the changes." The concept was written
first: `docs/design/0.4.0-document-and-saved.md`.

## Bugs fixed
| Bug | Cause |
|---|---|
| Save As opened no dialog | `icon_button` calls its action with no arguments; `on_save_as(self, _btn, …)` required one, so every click raised `TypeError` before the dialog opened |
| Save All had no icon | the hidden button was revealed with `show()`, which shows the button but not its child image; `show_all()` fixes it |

## Changed
- Preview → **Document**, Recent → **Saved**. Route ids (`preview`, `recent`) deliberately unchanged,
  so settings, `--page` and tests keep working.
- **Crops are new pages**: `apply_crop` flattens the source, writes the crop into the session folder
  and inserts a new page after the source *and its existing crops* (an early version inserted them in
  reverse order). Named by `crop_name(pages, source_name)` — `crop 1`, `crop 2`, … per source page,
  filling gaps left by deleted crops. The source page is never replaced.
- **Editable thumbnail captions** (`rename_page`, `safe_name`): the name replaces "Page n", is what
  Save calls the file and Save As pre-fills, and Ctrl+Z undoes it.
- **`suggested_name(pages)` only answers when unambiguous** — one page, or several sharing one name.
  Found because a 4-page document was nearly saved as "crop 2.pdf".
- **Toolbar regrouped**: History · Pages · Arrange · Edit (crop, text, signature) · Export.
- **Saved page**: search, `Gtk.Paned` with a collapsible preview expander (remembered as
  `saved_preview_open`), single click previews, double-click opens in Document, editable file-name
  cell renames on disk (refuses an existing name; `rename_recent` follows the entry).
- Layout faults caught in headless screenshots and fixed: the "nothing matches" line sat on the pane
  divider; the preview kept the last document after the list emptied; the preview pane did not fill
  its half until `vexpand` was set and the divider placed at 50 %.
